# Screen AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static website that watches a shared screen, reads the question on it, and shows the answer, using Claude (user key) or a free in-browser model.

**Architecture:** Plain ES modules, no bundler, no backend. Pure logic (frame diff, settings, request building) lives in small modules tested with `node --test`. Browser-only parts (capture, overlay, local model) are thin wrappers verified manually. `app.js` wires them to `index.html`.

**Tech Stack:** HTML/CSS/JS (ES modules), `getDisplayMedia`, Anthropic Messages API (direct from browser), Transformers.js (`@huggingface/transformers`, WebGPU), Document Picture-in-Picture, Node 20+ `node --test` for tests.

**Spec:** `docs/design.md`

## Global Constraints

- No backend, no build step; must work when served as static files (`python -m http.server`) — ES modules do not load from `file://`.
- API key stored only in `localStorage` under key `screenai.settings`; never logged, never hardcoded.
- Claude request headers: `x-api-key`, `anthropic-version: 2023-06-01`, `anthropic-dangerous-direct-browser-access: true`, `content-type: application/json`.
- Models: fast = `claude-haiku-5-5`, detailed = `claude-sonnet-5-5`. Local fallback default = `HuggingFaceTB/SmolVLM-256M-Instruct`.
- Watch mode interval 1500 ms; never send a new request while one is in flight.
- Frames sent to Claude are downscaled so the long edge is at most 1568 px, JPEG.
- Chrome/Edge desktop target; show a clear message if `getDisplayMedia` or WebGPU is missing.
- No features that hide the tool from screen capture or proctoring.

## Review Focus

- Missing/blank key → falls back to local engine, not an error.
- Pasted key with leading/trailing whitespace → trimmed before use.
- Claude returns 401/429/5xx or network failure → readable message in the overlay, app keeps working.
- User clicks the browser's "Stop sharing" during Watch → watch stops, UI resets.
- Huge (4K) screen → downscaled before sending.
- `localStorage` throws/unavailable → app still runs with defaults.
- Watch-mode tick arrives while a request is in flight → skipped.

### Task 3: Claude client

**Files:**
- Create: `src/claude.js`, `tests/claude.test.js`

**Interfaces:**
- Produces:
  - `buildRequest(apiKey: string, mode: "fast"|"detailed", imageBase64: string): { url: string, init: RequestInit }` — POST to `https://api.anthropic.com/v1/messages`, headers per Global Constraints, body with `model`, `max_tokens: 1024`, one user message containing an image block (`media_type: "image/jpeg"`) then a text block with `PROMPT`.
  - `PROMPT`: instructs the model to find the question on screen and answer it directly and accurately, reading every detail, and to say so plainly if no question is visible.
  - `parseAnswer(json): string` — joins `content[].text`; throws `Error` with the API's `error.message` when `json.error` exists.
  - `askClaude(apiKey, mode, imageBase64, fetchImpl = fetch): Promise<string>` — maps non-OK / network failure to `Error` with readable text (`"Invalid API key"` for 401, `"Rate limited, try again"` for 429, otherwise the status).

- [ ] **Step 1: Write failing tests** with a fake `fetchImpl`: header set exact; model is `claude-haiku-5-5` for fast and `claude-sonnet-5-5` for detailed; body has image block before text block; `parseAnswer` joins text blocks; 401 → "Invalid API key"; 429 → "Rate limited, try again"; rejected fetch → error message mentions network.
- [ ] **Step 2: Run** `npm test` — FAIL.
- [ ] **Step 3: Implement** `src/claude.js`.
- [ ] **Step 4: Run** `npm test` — PASS.
- [ ] **Step 5: Commit** `git commit -am "feat: claude client"`
